## まず、この結果が意味していること

今の出力はたぶん、

- 各 `mutType` について
- `mutNum / totalRootNum`
- を
- **全 mutation type 共通の global rate** `p = 1.006999e-02`

と比べる **二項検定** になっています。

つまり各行で聞いているのは、

> この mutation type の発生率は、全体平均の mutation rate と同じか？

です。

この設定だと、**ほぼ全部有意になるのは自然**です。理由は2つあります。

### 1. サンプルサイズが巨大
`totalRootNum` が数百万〜千万あるので、差が少しでもあると p 値が極端に小さくなります。

例えば：

- `A[C>T]G` rate = `1.184052e-02`
- global p = `1.006999e-02`

差は絶対値で見ると **0.00177くらい**ですが、試行回数が300万超なので、検定上は「超有意」になります。

### 2. そもそも mutation spectrum は平らではない
このパイプラインの主題そのものが **context dependency** なので、
`C>T` 系が多いとか `T>A` 系が少ないとかは最初から普通に起こる。

だから

> 「全 mutation type が同じ rate か？」

を聞くと、ほぼ確実に全部外れます。

## 何が変なのか

### 変な点1：global rate を全部に使っている
`C>A`, `C>G`, `C>T`, `T>A`, `T>C`, `T>G` は、そもそも平均頻度が全然違います。

たとえばあなたの表でも、

- `C>T` はだいたい高い
- `T>G` はだいたい低い

ですよね。

この状態で全部を同じ `global p` と比べると、

- `C>T` は「高すぎる」→有意
- `T>G` は「低すぎる」→有意

となって、**当たり前のことを当たり前に再確認しているだけ**になります。

## より自然なやり方

### 案1：置換クラスごとに検定する
たとえば `C>T` の16 context だけ取り出して、

- `p_C>T = sum(mutNum[C>T]) / sum(totalRootNum[C>T])`

を作り、
各 `A[C>T]A`, `A[C>T]C`, ... を **C>T クラス内平均** と比べる。

同様に

- C>A の16個
- C>G の16個
- C>T の16個
- T>A の16個
- T>C の16個
- T>G の16個

それぞれでやる。

これなら聞いている問いが

> この context は、同じ置換クラスの中で特に多い/少ないか？

になるので、かなりマシです。

---

### 案2：二項検定よりカイ二乗＋残差を見る
repo にある `chi2_context.py` / `chi2_context.R` の方が、
たぶんこの目的にはむしろ自然です。

やりたいことが

> 「context 依存性があるか？」
> 「どの context が期待より多いか？」

なら、

- まず全体で **χ²検定**
- その後に **標準化残差** や `log2(obs/exp)` を見る

のが分かりやすいです。

---

### 案3：p値より effect size を主役にする
この規模のデータでは p 値はほぼ何でも有意になりがちなので、

- `rate`
- `expected rate`
- `log2(observed / expected)`
- 信頼区間

を出す方が実質的です。

# 補正は必要？
## はい、**行ごとに有意/非有意を付けるなら必要**です

---

## なぜ補正が必要？
あなたはいま **1回のファイルに対して大量の仮説検定** をしています。

この表は 96 行ありますよね。

つまりこの1ファイルだけで、

- 96個の帰無仮説
  - `A[C>A]A` の rate は期待と同じ
  - `A[C>A]C` の rate は期待と同じ
  - ...
  - `T[T>G]T` の rate は期待と同じ

を同時に検定しています。

これが **多重検定** です。

---

## 何が「多重」なの？
**多重なのは p値の数**です。

1つの TSV に対して：

- 96 個の `mutType`
- → 96 個の p 値

これが「多重」。

もし全 species / 全 trio / 全 whole+ncds までまとめるなら、さらに何千何万テストになります。

---

## 補正しないと何がまずい？
有意水準 0.05 を各検定にそのまま使うと、
全部の帰無仮説が本当でも、**偽陽性**がかなり出ます。

96個テストなら、期待される偽陽性数はざっくり

- `96 × 0.05 = 4.8`

です。

「少なくとも1個は偽陽性」になる確率もかなり高いです。

---

## じゃあどの補正？
普通はこのどちらかです。

### 1. Bonferroni
厳しめ。
`0.05 / 96 ≈ 5.2e-4`

### 2. BH (Benjamini-Hochberg, FDR)
実務的にはこれが使いやすいです。
とくに genome-wide 的な「多数の候補からシグナルを拾う」用途では BH が自然。

---

## でも今回、補正すると結果は変わる？
**たぶん変わりません。**

p 値が `1e-323` とか `1e-206` とかなので、
Bonferroni でも BH でも全部有意のままです。

なので今回の本質は

- **補正不足**ではなく
- **帰無仮説が単純すぎる**

です。

---

# もう1つ大事な点
## この binomial test は「独立試行」をかなり仮定している
trinucleotide はゲノム上で1塩基ずつずれて重なるので、完全には独立じゃありません。
さらに局所的な mutation clustering や alignment 依存もあります。

だから **p 値を厳密な意味で信じすぎない方がいい**です。
この種のデータでは、p値より **効果量** を重視した方が安全です。
