EvoSubster / implementation plan

Newick 入力による trio 選別

系統樹を入口に、論文 §2.3 の選別規則（実測 sequence percent identity + genus name）を last-train 経由で適用し、最終的に sbst_fromDwl.sh の --tree モードとして組み込む。

CONTEXT

なぜ変えるか

現行の trio_selection.R は樹の patristic distance を疑似 identity (100 - patr_dist) に変換し、論文の方法ではない parsimony_ratio() で足切りしている。パイプラインにも繋がっておらず、 閾値もハードコードされたプロトタイプの状態。

論文 §2.3 が実際に使っているのは実測のアラインメント identity と属名であり、 樹の距離ではない。そしてその規則は src/report/collect_run_summary.py の evaluate_filter_status (192-244行) に既に実装済みで、§2.3 と 1:1 で対応している。

論文 §2.3collect_run_summary.py
全ペアの identity > 80% threshold_condition（--idt-threshold, 既定 80）
属パターンが A≠B, A≠C, B=C → 常に採用 genus_condition = pattern1
否なら IdAB < IdBC かつ IdAC < IdBC idt_12 < idt_23 and idt_13 < idt_23
ただし外群が内群の片方とだけ同属なら除外 pattern5

属名は何を判定しているのか（pattern5 の意味）

trio は ((B,C),A)——外群 A が内群 B・C の両方から等しく外側にいる—— という topology を前提にしている。「外群と片方の内群が一致したら、もう片方が変異した」という パーシモニーの推論は、この前提が崩れた瞬間に意味を失う。 属名はその前提に対する安価な反証テストとして使われている。

属の配置topology への含意扱い
pattern1 A≠B, A≠C, B=C 内群2種が同属、外群だけ別属。前提を積極的に支持 identity 順序を見ずに無条件採用
pattern3 3種とも同属 属名が3種を区別しない → 情報なし identity 順序に判断を委ねる
pattern4 3種とも別属 属名が3種を等しく分ける → 情報なし identity 順序に判断を委ねる
pattern5 A=B, C≠ または A=C, B≠ 外群が内群の片方とだけ同属——分類学は ((A,B),C) だと言っている。前提と正面から矛盾 除外

pattern3 と pattern4 が「許容」なのは、属名が正しさを保証しているからではなく、 反証を出していないから。判断材料がないので実測 identity の順序 (Id_AB < Id_BC かつ Id_AC < Id_BC = 内群ペアが最も似ている) に委ねる。 対して pattern5 では属名が「A は C より B に近い」と能動的に主張しており、 これは外群の定義そのものへの反証なので、identity の順序が通っていても却下する。 ——つまり属名は採用の根拠ではなく、拒否の根拠として効いている。

→

コード上は org1 が外群なので pattern5 = (org1==org3 && org1!=org2) || (org1==org2 && org1!=org3) （collect_run_summary.py:135-146）。「2対1」という言い方は 3種が属で 2 : 1 に割れ、その割れ目が内群/外群の境界と一致していない状態を指す。 pattern1 も 2 : 1 に割れているが、そちらは割れ目が境界と一致している。

したがって規則を書き直すのではなく、再利用するのが正しい。 設計を縛る事実が2つある。

1

樹だけでは trio を決められない。 Primates_tree.nwk は厳密に ultrametric（＝全ての葉が root から等距離。 実測した root-to-tip 深度のばらつきは 7.3e-10 しかない）。

ultrametric な樹では、外群 A は内群 B・C から必ず等距離になる。 つまり Id_AB == Id_AC が恒等的に成立し、 内群ペアの Id_BC は topology 上つねにそれより大きい。 すると論文の順序判定 Id_AB < Id_BC かつ Id_AC < Id_BC は——

「判定できない」のではない。「常に成立してしまう」のだ。 実際に Primates_tree.nwk で全 trio を列挙して樹の距離で判定すると:

trio 列挙数                        : 12291
Id_AB == Id_AC                    : 12291 / 12291   (max |diff| = 4.0e-10)
順序判定が通る                    : 12291 / 12291   (= 100%)

フィルタとして 1 件も落とさない = 選別能力ゼロ。 理由は単純で、この順序判定は本来内群2種の進化速度の非対称性を検出するためのものだが、 ultrametric な樹はその非対称性を定義上ゼロに潰しているから。 樹に埋まっていない情報は樹からは取り出せない。

したがって樹の役割は trio の列挙と粗い深さの事前絞り込みだけ。 本審査には last-train の実測 identity が要る—— 実際のゲノム配列は ultrametric ではないので、そこで初めて速度の非対称性が数字に出る。

2

last-train が支配的コスト。だから trio 単位で回してはいけない。 last-train は種ペアに対して1回走る（trio 1つにつき3ペア）。 そして候補 trio は種を大量に共有するので、trio ごとに素直に回すと 同じ種ペアを何度も再計算することになる。

霊長類 37種の場合:

trio 単位で回す : 12291 trio × 3 ペア = 36873 回の last-train
種ペア単位      : 37種から作れるペアは全部で 666 通りしかない
                  → 最悪でも 666 回。実際は候補に出てくるペアだけなのでさらに少ない

キャッシュの単位を「trio」ではなく「ユニークな種ペア」にする。 幸い last_train.sh は .train ファイルが既にあればスキップする作りなので、 出力ディレクトリを全 trio で共有するだけで再利用が効く（実装コストはほぼゼロ）。

STEP 1

論文の規則を1箇所に集約

src/select/trio_filter.py を新設し、以下を collect_run_summary.py からそのまま移す:

  • extract_genus_label
  • evaluate_genus_patterns
  • parse_identity_percentage
  • evaluate_identity_condition
  • evaluate_filter_status

collect_run_summary.py は定義を消して import に置き換える。 純粋な移動なので挙動は不変——レポート出力はバイト一致しなければならない。

R から一括で呼べるようバッチ CLI を足す:

python3 src/select/trio_filter.py \
    --trios trios.tsv --idt-threshold 80 --out verdict.tsv

# 入力 TSV:  out_acc  in1_acc  in2_acc  idt_12 idt_13 idt_23  genus_1 genus_2 genus_3
# 出力 TSV:  入力列 + filter_details の全キー (excluded, genus_condition_met, ...)
!

ラベル規約に注意。コードベースは一貫して org1 = 外群, org2/org3 = 内群。 つまり idt_12, idt_13 が外群-内群、idt_23 が内群ペア。

論文は逆の文字を使っている（A = 外群）。式をそのまま写すと外群と内群が入れ替わる。

STEP 2

trio_selection.R の書き換え

Stage 0  樹の葉を 1種1アセンブリに剪定       [NCBI metadata, 1 API call]
Stage 1  trio 列挙 + 樹による事前絞り込み      [tree only, 無料]
Stage 2  候補に含まれる accession のみ DL      [dwl_organism.sh]
Stage 3  ユニークな種ペアごとに last-train    [last_train.sh, 共有キャッシュ]
Stage 4  論文の規則で最終選別                  [trio_filter.py]

Stage 0 — 1種1アセンブリに剪定

全葉の accession を 1回のバッチ呼び出しで dataset_report 取得 (?page_size=1000——既定のページサイズは20で黙って切り捨てる)。 種ごとに最良のアセンブリを残す: assembly_info.refseq_category == "reference genome" を優先し、無ければ assembly_level / contig N50 でフォールバック。

→

厳格に reference genome のみにすると霊長類 37種中 11種が丸ごと脱落する (M. mulatta, Pan paniscus, Pongo abelii 等)。 best-per-species なら 37種を維持したまま重複除去できる。

NCBI が返さなくなった accession（GCA_037993035.1 は既に消滅）は警告して葉ごと落とす。

Stage 1 — 列挙と事前絞り込み

既存の descendant_tips() / sister_tips() をそのまま再利用する。 これらは ((B,C),A) の topology を構成的に保証している。 葉ラベルは Genus_species_ACCESSION なので genus は第1トークン—— 無料で属の事前判定に使える。

樹 identity 100 - patristic（枝長はpercent sequence difference）で絞るが、 --idt-threshold より緩いマージンを取る。樹の identity は 実測 identity の近似にすぎず、厳格に切ると実データなら通る trio を捨ててしまうため。 clade あたりの候補数に上限を設けてコストを縛る。

DEL

parsimony_ratio() と BALANCE_DELTA を削除する。 ultrametric な樹では p_B == p_C が恒等的に成立するので両方とも無意味であり、 そもそも論文の方法ではない。

Stage 2-3 — ダウンロードと last-train

生き残った候補に含まれる accession だけ src/dwl_organism.sh で取得（既に冪等）。 次に全候補 trio からユニークな無向種ペアを集め、ペアごとに1回だけ: 

src/align/last_train.sh <DATE> <fa2> <fa3> <short2> <short3> <shared_cache_dir>

last_train.sh は .train が存在すればスキップするので、 out_dir を共有するだけで trio 間の再利用が無料で効く （lastdb も種ごとに1回で済む）。 identity は # substitution percent identity: 行から取る。

Stage 4 — 最終選別

trio テーブルを書き出し、trio_filter.py を system2() で1回だけ叩き、 判定を join して selected_trios.tsv を出す。

新しいオプション

--tree, --idt-threshold（既定 80）, --prescreen-margin, --top-k, --genome-dir, --out-dir, --date

STEP 3

sbst_fromDwl.sh に --tree モード

--tree <file.nwk> を追加し、指定時は4つの位置引数を省略可能にする。 trio_selection.R を実行し、選別された各 trio に対して通常のパイプラインを回す。 --idt-threshold は R まで通す。

→

スクリーニングで sbst_fromDwl.sh を再入させないこと。 trio_selection.R は dwl_organism.sh / last_train.sh を 直接呼ぶので再帰は起きない。

  • リファクタが無害であること: 既存の results ディレクトリに対して collect_run_summary.py を移動前後で実行し、JSON が diff で一致すること。
