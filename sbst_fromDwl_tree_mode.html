sbst_fromDwl.sh の Tree mode — 系統樹一枚からTrioを選び、パイプラインを回すまで

通常の sbst_fromDwl.sh は「外群1種＋内群2種」の3アクセッションを手で指定して1トリオずつ実行する。 Tree mode（--tree FILE.nwk）はこれを自動化し、Newick系統樹を1枚渡すだけで 「木の上のどのペアを内群にし、どの種を外群にするか」を src/select/trio_selection.R に選ばせ、 選ばれたトリオぶんだけ通常モードのパイプラインをループで実行する。

STEP 0

全体の流れ

Tree modeは2つのフェーズに分かれる。フェーズ1（選抜）は trio_selection.R が1回だけ走り、木からトリオ候補表 selected_trios.tsv を作る。 フェーズ2（実行）は sbst_fromDwl.sh 自身がその表を1行ずつ読み、 毎回「通常の単一トリオモード」として自分自身を再帰的に呼び出す。

Newick木
(*.nwk)→ trio_selection.R
Stage 0: 種ごとに最良アセンブリ選定→ Stage 1: ペアごとに外群探索→ selected_trios.tsv
selected_trios.tsv→ sbst_fromDwl.sh
行ごとにループ→ sbst_fromDwl.sh
(単一トリオモードで自分自身を再帰呼び出し)→ dwl_organism.sh ×3
+ sbst.sh
→ トリオ選抜そのものはR側で完結しており、シェル側は「選ばれた行を読んで既存パイプラインをもう一度呼ぶだけ」の薄いループになっている。 選抜ロジックを変えたいときは trio_selection.R／trio_filter.py だけを触ればよい。
STEP 1

エントリーポイントとオプション解析

sbst_fromDwl.sh は先頭のオプションパーサーで --tree を受け取ると TREE_FILE を設定する。この変数が空でなければ、通常モードに必須の DATE ACC1 ACC2 ACC3 4引数チェックはスキップされ（Tree modeでは位置引数は使わない）、 DATE だけ省略時に今日の日付が補われる。 

# src/sbst_fromDwl.sh:271-277 — 必須引数チェックは Tree mode を素通りする
if [ -z "$TREE_FILE" ] && { [ -z "$DATE" ] || [ -z "$org1ID" ] || ... }; then
    ... # 通常モードのみここで exit 1
fi
Tree mode専用オプション既定値意味
--tree FILE.nwk必須入力のNewick木。葉ラベルの末尾にNCBIアクセッション（例: GCA_000001405.29）が必要。
--idt-threshold N80trio内のどのペア識別率もこの値を超えなければ棄却。
--max-outgroup-tries N51つの内群ペアあたり、thesis ruleに通らないまま外群候補をtrainingし続ける上限回数。
--ingroup-pairing MODEmatchingmatching=近い順の貪欲な排他マッチング／all=全ペア総当たり。
--min-rel-contig-n50 F0（無効）相対contig N50によるアセンブリ品質ゲート（後述）。

これ以外の --genome-dir / --out-dir / --thread / --idt-only / --force は通常モードと共通で、Tree modeでもそのまま使える （--idt-only・--force の効き方は STEP 9 を参照）。

STEP 2

trio_selection.R の呼び出し

Tree modeブロックに入ると、出力先を $out_dir_base/trio_selection に固定し、 収集したオプションを引数に組み立てて Rscript を1回だけ呼ぶ。 

rt_out_dir="$out_dir_base/trio_selection"
r_args=(--tree "$TREE_FILE"
        --genome-dir "$base_genomes"
        --out-dir "$rt_out_dir"
        --date "$DATE"
        --threads "$THREAD_NUM_OVERRIDE")
# --idt-threshold / --max-outgroup-tries / --ingroup-pairing / --min-rel-contig-n50 は
# 指定されたときだけ追記される（未指定ならR側の既定値がそのまま使われる）

Rscript "$SCRIPT_DIR/select/trio_selection.R" "${r_args[@]}"

ここで生成物は選抜専用のサブディレクトリ trio_selection/ にまとまる。 あとで各トリオの実解析結果を書き込む $out_dir_base/<combo>/<DATE>/ とは別の場所なので、 「選抜のログ・キャッシュ」と「解析結果」が混ざらない。

STEP 3

Stage 0 — 木の葉を「種ごとに最良の現行アセンブリ」へ間引く

入力の木は「葉＝1アクセッション」だが、そのアクセッションが必ずしも今その種で使うべき最良のゲノムとは限らない （古い草稿版、廃止済み、より連続性の高い版が別に存在する、等）。Stage 0はダウンロード前に 種名だけを手掛かりにNCBIから候補を集め直し、木を「種ごとに1本の葉」まで刈り込む。

3-1. 葉ラベルの解析

葉ラベルは Genus_species_..._GCA_000000000.1 の形式を仮定する。 正規表現 GC[AF]_[0-9]+\.[0-9]+$ で末尾のアクセッションを切り出し、 残りの先頭2トークンを "Genus species" として種名にする （fetch_assembly_metadata.py 側の名前パースと揃えてあるので、そのままNCBI照会に使える）。

3-2. 全アセンブリを取得し、品質ゲートをかける

木の全種名 → tree_taxa.txt→ fetch_assembly_metadata.py
（種ごとに現行の全アセンブリをNCBIから取得）→ assembly_metadata.tsv

select_best_assemblies() はこの表に対して次の順で絞り込む。

順序条件・基準ねらい
①assembly_status == "current"撤回・置換済みのアセンブリを除外
②相対contig N50 = contig_n50 / total_ungapped_length ≥ --min-rel-contig-n50（>0のときのみ）絶対値のcontig N50はゲノムサイズが違う分類群間で比較不能なので、ゲノム長で正規化してから閾値をかける
③種ごとに desc(is_reference)「reference genome」指定があれば最優先（連続性が多少低くても勝つ）
④→ desc(contig_n50)同格ならより連続的なアセンブリを選ぶ
⑤→ desc(has_annotation) → level_rank（Complete Genome > Chromosome > Scaffold > Contig）アノテーション有無・アセンブリレベルは最後の僅差判定に使う
⑥→ desc(accession)完全に同格な場合の決定論的なタイブレーク

各種につき先頭1件（slice_head(n=1)）だけを残す。

! 種の全アセンブリがゲートに落ちる、あるいはNCBI側にその種名で一致するアセンブリが1件もない（別名・再分類の疑い）場合、 その種は木から丸ごと落ちる。ログには「NCBIメタデータが1件もない種」と「ゲートで落ちた種」を分けて出力する。 同じ種名の葉が複数あるときは、木の順で最初の1枚だけを残して残りは畳み込む。

3-3. 木を刈り込む

生き残った種の葉だけを残して drop.tip() で木を刈り込み、各葉に選ばれたアクセッション・短縮名 （make_short_names()：属種の頭3文字＋3文字、衝突時のみ連番を付与）を付け直す。 この結果は selected_assemblies.tsv に書き出され、Stage 1のleaves表としてそのまま使われる。

重要な点: Stage 0で選ばれるアクセッションは、木の葉ラベルにあった元のアクセッションと 一致するとは限らない（より良い版に自動で差し替わる）。したがって以降のStage 1・パイプライン実行は すべてこの「選び直された」アクセッションに対して行われる。

STEP 4

Stage 1a — どの2種を内群ペアにするか（--ingroup-pairing）

Stage 1は「まず内群ペアを決め、そのペアに対して外群を探す」という順で進む。ペアの選び方は2モード。

matching（既定）— 近い順の貪欲な排他マッチング

各枝長を1に揃えた木で cophenetic() を取り、2葉間の距離を「間にある枝の本数」として測る （実測の枝長ではなくトポロジーだけを使う。理由: 進化速度の違いや加法的な枝長では、 真の姉妹ペアより非姉妹ペアの方が枝長合計が短くなることがあり、それを避けたい）。 外群が存在しないペア（MRCAが根＝root）はあらかじめ除外したうえで、

全ペアを近い順にソート
（タイブレーク: 相対contig N50合計 desc → 葉名）→ 近い順に貪欲に確定
使用済みの種は以後スキップ→ 互いに素な ~n/2 組の姉妹ペア

木が完全に二分岐（各内部ノードが2つの子を持つ）なら、真の姉妹種（cherry、距離=2本の枝）が最優先で組まれる。 梯子状（ladder）の系統樹では一部の種が誰とも組まれずに余ることがある——それは仕様であり、無理に遠縁同士を組ませない。

all — 全ペア総当たり

木の葉から combn(n, 2) で全組み合わせを列挙する（C(n,2) 通り）。 再設計前の挙動を残した網羅・検証用のオプトアウト経路で、種数が多い木では last-train 実行回数が跳ね上がる点に注意。

STEP 5

Stage 1b — 外群候補を「近い順」に並べる

内群ペア (tipA, tipB) が決まったら、candidate_outgroups() が そのMRCA（最も近い共通祖先）から根に向かって1段ずつ登りながら、各段の「きょうだいクレード」を候補として集める。 同じ段の中では相対contig N50が高い方を先に試す（木は超計量なので枝長では優劣がつかないため）。

tipA・tipBのMRCAから根へ1段ずつ登るたびに、通り過ぎたノードの「もう一方の子」の下にいる全ての葉が 1つの候補グループになる。根に達したら（＝これ以上登れない＝外群が存在しない）探索を打ち切る。

木のMRCAが根そのもの（＝そのペアより外側に何も残っていない）の場合、候補は0件——このペアは外群を持てないので Stage 1の集計上「no outgroup on tree」としてカウントされ、trioは選ばれない。

STEP 6

Stage 1c — 候補を1つずつ試し、最初にthesis ruleを通った時点で確定

内群ペアごとの本体ループ（select_trios()）は次の順で動く。

ペア単位の前提チェック（外群探索の前に1回だけ）

  • 候補が0件 → no_outgroup としてスキップ
  • 内群ペア自体の識別率 idt_23 を1回だけtrainingし、≤ --idt-threshold なら too_diverged としてこのペアごと諦める（外群を探すまでもなく内群ペアが離れすぎている）

候補ごとのループ（近い順）

外群候補1件ごとに、まず無料の事前フィルタ（trainingを1回も呼ばない）をかける。 外群の属（genus）が内群2種のうちちょうど片方とだけ一致する「2対1」の分類だと、 thesis ruleは識別率に関わらず必ず棄却するため（is_two_vs_one()）、その候補はtry回数を消費せず即スキップする。

通過した候補だけが --max-outgroup-tries の消費対象になり、外群↔内群2種の識別率 idt_12・idt_13 を last-train でtrainingしたうえで、 trio_filter.py（thesis rule、STEP 7で詳述）に1行だけ渡して判定する。

PASSexcluded == FALSE このトリオを確定して即座にループを打ち切る（それ以上遠い候補は試さない＝一番近い合格候補を採用）。
STOPidt_threshold_condition == FALSE 識別率のどれかが閾値を下回った＝「遠すぎ」。これより外側の候補はもっと遠いので、探索窓が閉じたと判断してこのペアを諦める（break）。
NEXTそれ以外（識別率順序 idt_12<idt_23 かつ idt_13<idt_23 が不成立） 「近すぎ／トポロジーと矛盾」＝この候補はだめだが、まだ閾値内なので次の（より遠い）候補を試す。

--max-outgroup-tries 回trainingしても合格が出なければ no_valid_outgroup として このペアは諦める。最終的にペアごとに最大1トリオだけが選ばれる。

→ ダウンロード・last-trainingは make_fetchers() がメモ化する。 種のペア（順不同で正規化した短縮名キー）ごとに一度trainingしたら結果をR側のキャッシュに保持し、 別の内群ペアの外群候補として同じ種が再登場しても再trainingしない。ディスク上のtrainファイルも --date 単位でキャッシュされるため、同じ日付で再実行すればさらに再利用される。
STEP 7

thesis rule（trio_filter.py）— 1トリオを合格／棄却させる唯一のロジック

trio_filter.py は論文2.3節のルールを実装した単一のソースで、 trio_selection.R（Stage 1の逐次判定）と src/report/collect_run_summary.py （実行後レポート）の両方から呼ばれる。入力は識別率3つ（idt_12, idt_13, idt_23）と 属名3つ（genus_1=外群, genus_2・genus_3=内群）。

① 識別率パターン

条件意味
idt_threshold_condition3つの識別率すべてが --idt-threshold を超える。これがFALSEなら他条件に関わらず即棄却（最優先ゲート）。
identity_condition_metidt_12 < idt_23 かつ idt_13 < idt_23。「内群ペア同士が、外群とのペアよりも近い」というトポロジー整合性チェック。

② 属名パターン（genus_1=外群, genus_2/genus_3=内群）

パターン条件扱い
pattern1（目標形）外群だけ別属、内群2種は同属識別率順序を問わず常に合格（分類学的に理想形なので即採用）
pattern33種とも同属identity_condition が真のときのみ合格
pattern43種とも別属identity_condition が真のときのみ合格
pattern5（2対1）外群が内群のちょうど片方とだけ同属識別率に関わらず常に棄却（分類が外群の位置づけと矛盾するため）

Stage 1側の is_two_vs_one() はこのpattern5だけを先回りしてチェックする軽量な複製で、 「どうせ棄却されるとわかっている候補」をtrainingする前に弾くための最適化になっている。

✕ 属名が取れない（メタデータ欠落）・識別率が数値としてパースできない場合は、その項目の判定結果が NA になり、最終的に filter_flag も確定しない＝安全側で棄却扱いに倒れる。
STEP 8

出力ファイルとディレクトリ構成

$out_dir_base/trio_selection/
├── tree_taxa.txt              # Stage 0: 木から抽出した種名リスト
├── assembly_metadata.tsv      # Stage 0: NCBIから取得した全アセンブリのメタデータ
├── selected_assemblies.tsv    # Stage 0: 種ごとに選ばれた最良アセンブリ（刈り込み後の葉と対応）
├── train_cache/                # Stage 1: last-train結果 (*.train) のキャッシュ、日付単位
├── candidate_outgroups.tsv    # --dry-run 時のみ: ペアと候補外群の並び順
└── selected_trios.tsv         # Stage 1: 最終的に選ばれたトリオ一覧（1ペア=最大1行）

selected_trios.tsv の主な列:

列内容
out_acc / in1_acc / in2_acc外群・内群1・内群2のアクセッション（sbst_fromDwl.shが読むのはこの3列だけ）
out_tip / in1_tip / in2_tip元の木の葉ラベル
out_species / in1_species / in2_species解析された種名
idt_12 / idt_13 / idt_23合格時点での3ペア識別率（%）
outgroup_tries合格するまでに実際にtrainingした候補数
STEP 9

sbst_fromDwl.sh に戻ってループ実行

R側が正常終了したあと、シェル側は selected_trios.tsv のヘッダ行を読んで out_acc・in1_acc・in2_acc の列番号を名前で解決する （列の並びが変わってもシェル側は壊れない設計）。 

pass_opts=(--genome-dir "$base_genomes" --out-dir "$out_dir_base" --thread "$THREAD_NUM_OVERRIDE")
[ "$IDT_ONLY" -eq 1 ] && pass_opts+=(--idt-only)
[ "$FORCE_DOWNLOAD" -eq 1 ] && pass_opts+=(--force)

while IFS=$'\t' read -r out_acc in1_acc in2_acc; do
    bash "$SCRIPT_DIR/sbst_fromDwl.sh" "$DATE" "$out_acc" "$in1_acc" "$in2_acc" "${pass_opts[@]}"
    # 失敗しても trio_failures をカウントするだけで次のトリオへ進む
done < <(awk ... "$selected_file")

つまり --tree が付いた1回の起動は、内部的には 「--tree なしの単一トリオ呼び出し」を選ばれたトリオの数だけ逐次実行するのと同じになる （再帰は1段だけ——子呼び出しに --tree は渡らないので無限再帰にはならない）。 各子呼び出しは通常モードそのものなので、ダウンロード → GFF検出 → メタデータマニフェスト生成 → sbst.sh（アライメント〜TSV出力）まで、CLAUDE.mdに書かれた通常のパイプライン全体を1トリオぶん実行する。

! 1トリオが失敗しても処理は止まらず、警告を出して次のトリオへ進む。全トリオ処理後、 1件でも失敗があればスクリプト全体の終了コードが1になる（CIやバッチ実行での失敗検知用）。 逐次実行なので並列化はされていない——トリオ数が多い木では相応の時間がかかる。
STEP 10

オプション早見表と、知っておくと便利な細部

オプション効く範囲備考
--idt-thresholdStage 1 (R)省略時はR側の既定80が使われる
--max-outgroup-triesStage 1 (R)ペアあたりのlast-trainコスト上限。pattern5（2対1）のスキップはこの回数を消費しない
--ingroup-pairingStage 1 (R)all は種数が多いほどlast-train回数が急増する点に注意
--min-rel-contig-n50Stage 0 (R)0=無効。値を上げすぎると種がまるごと木から落ちる
--idt-onlySTEP 9の子呼び出しのみStage 1自身のtrainingには効かない（Rは常にthesis rule判定まで行う）
--forceSTEP 9の子呼び出しのみtrio_selection.R側のダウンロード・last-trainには渡らない＝選抜フェーズは常にキャッシュ優先
--dry-runtrio_selection.R 直接実行時のみsbst_fromDwl.sh --tree からは現状渡せない。ペア構成と候補順だけ確認したいときは Rscript src/select/trio_selection.R --tree FILE.nwk --dry-run を直接叩く
→ まず木の妥当性やペア構成だけ確認したいときは、--dry-run （ダウンロード・trainingなしで candidate_outgroups.tsv を出力）をR側で直接試してから、 本番の sbst_fromDwl.sh --tree 実行に進むと無駄なNCBIアクセスを避けられる。
